SYSTEM FAQ // E2E ENCRYPTED • ZERO FILE STORAGE
How does DarkP2P work without server storage?

Files stream directly browser-to-browser over WebRTC DataChannels. The signaling server only pairs two peers in RAM. When a direct connection is not possible, it forwards the already-encrypted chunks through memory. It never writes file data to disk or logs it.

Can the server read or decrypt my files?

No. Every chunk is encrypted in your browser with AES-256-GCM. The keys are derived from a 256-bit secret that exists only in the URL fragment (after #), which browsers never send to the server.

What can the server see?

Not your files, their names or the key. It does see connection metadata: your IP address (held in memory only as a salted hash for rate limiting, never logged), the room ID, and, when the WebSocket relay is used, how many bytes pass through and when.

Is there a file size limit?

Not for direct P2P transfers: the server sets no cap, and incoming chunks stream to disk (a file you choose, or the browser's Origin Private File System) instead of RAM. The WebSocket relay, which Tor Browser always uses, is capped at 50 MB per room (500 MB with Pro). Browsers that cannot stream to disk are limited to 512 MB.

Does WebRTC hide my IP address?

No. Direct P2P connections expose your IP address to the other peer during NAT traversal. To hide it, turn on Force WebSocket relay, turn on Hide my IP with a Pro token, or use a zero-log VPN or Tor Browser.
